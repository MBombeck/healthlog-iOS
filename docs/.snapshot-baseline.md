## Lock category

All 19 snapshots are **structural-only** (not locked-pixel). They capture the
data dictionary that drives the view, not the rendered appearance. As a
consequence:

- Visual Theme-track changes (colour, blur, ring stroke, sparkline shape,
  Liquid Glass chrome, accent sweep, spacing rhythm) are **invisible** to
  these tests by design. They are guarded by build + manual visual review
  on simulator.
- Drift-detection is for **data-contract** changes (new state keys, renamed
  state fields, polarity/format changes on `HLTileDescriptor`,
  trend-polarity matrix shape). C-1...C-11 introduced none.
- Regen is a no-op against `group-4-merged` — all 19 snapshots match the
  current code on disk (`xcodebuild test -only-testing:HealthLogTests`
  reports 759/759 green incl. snapshot tests).

## Pixel-locked snapshot policy (future)

When pixel snapshots arrive (planned post-v0.5.x for Settings rows + Dashboard

simulator walkthrough during each C-N phase.

## Canonical visual baseline (post-Theme)

Locked by code on `feat/v05x-theme-c12`:

- **Monochrome chrome** — bars, tab-bar, side-by-side gradients removed
  (C-1, C-2). Accent surfaces only on focal points.
- **Charts** — `AreaMark` dropped, `LineMark` only with `HLColor.purple`
  stroke. `HLSparkline` line-mode only (no fill).
- **Rings** — single-stroke `HLRing`, no inner gradient. Score-ring uses
  `purple`, sub-rings use neutral grey for context-rings.
- **TrendChip** — flat fill, no shadow, no border. Polarity-aware colour via
  `HLColor.trend(_:_:)`.
- **Liquid Glass** — `HLScreenBackground` + `LiquidGlass.swift` provide
  glass surfaces on tab-bar background and Settings sheet headers (iOS 26+
  primary, graceful fallback to material on iOS 18).
- **Accent sweep** — `HLColor.purple` is the single brand accent. Tinted
  in 48 surface sites (chips, score-ring, primary CTA, dashboard active
  tile-state).
- **Spacing rhythm** — `HLSpace` tokens (`hair=1`, `xxs=2`, `xs=4`, `chip=6`,
  `sm=8`, `md=12`, `lg=16`, `xl=20`, `xxl=24`, `xxxl=32`, `xxxxl=40`).
  Grep on `HealthLog/Screens` + `HealthLog/DesignSystem` for literal
  `padding(N)` / `spacing: N` (where `N != 0`) returns zero matches.

## Regen procedure (for future Theme passes)

1. Set the snapshot-test recording flag in the test target (`SnapshotTesting`
   `isRecording = true` in the suite's `setUp`).
2. Run `xcodebuild ... -only-testing:HealthLogTests test` — snapshot files
   rewrite on first run, tests "fail" once with recording-mode signal.
3. Review the new files (`git diff HealthLogTests/.../__Snapshots__/`).
4. Accept only if the diff is justified by the change being shipped.
5. Reset `isRecording = false`. Commit.

For C-12 the regen was a no-op — running tests against the current code
produced no snapshot diff, confirming the post-Theme code on
`group-4-merged` is byte-equivalent at the data-dictionary layer to the
pre-Theme baseline.
